# SimpleFramework 全库审查设计

## 目标

在独立分支上对整个解决方案进行多轮、可验证的代码审查与修复，使各模块在保持轻量和易读的前提下具备可上线的易用性、健壮性与稳定性。项目尚未对外发布，因此允许改进公共 API；任何破坏性变更都必须带来明确的正确性或易用性收益，并同步维护中文 XML 注释和关键行为测试。

## 审查原则

- 采用“分模块穷尽审查 + 风险优先修复”的混合方式。
- 优先处理会导致错误结果、状态损坏、资源泄漏、并发竞态、明显性能浪费或难以诊断失败的问题。
- API 以调用者体验为准，可以删除、重命名或调整尚未发布的不合理接口，但不为风格偏好进行大规模重写。
- 公共类型和成员必须有准确的中文 XML 注释；注释描述实际契约，而不是逐字复述名称。
- 凡适合 `net8.0` 的现代 C# 语法能让代码更简洁、清晰，就应采用；不为追新使用晦涩写法。
- 减少重复、无效防御和低价值测试，不以压缩行数为目的牺牲语义清晰度。
- Net 模块仍检查协议正确性、并发、生命周期、资源释放、性能和异常恢复，但网络安全防护不作为本轮上线门槛。

## 轮次划分

### 第一轮：核心框架与项目契约

审查根项目配置、Domain 生命周期、组件注册与查找、事件、命令、查询和可绑定属性。重点验证所有权、初始化/释放幂等性、父子域边界、空值契约及公共 API 一致性。

### 第二轮：基础模块

审查 Collections、Utility、Toolkit 和 Maths。重点验证集合边界、枚举与比较语义、文件和序列化失败模式、任务/时间行为、配置读写、矩阵和网格算法的异常输入。

### 第三轮：Patterns

审查单例、服务定位器、对象池、消息通道、黑板和层次状态机。重点验证重入、重复注册、资源归还、并发访问、父级查找与状态转换顺序。

### 第四轮：ECS

审查 World、Entity、Archetype、Query、CommandBuffer、Prefab 和 SystemGroup。重点验证结构变更、查询更新、实体生命周期、组件列一致性、命令回放以及系统依赖排序。

### 第五轮：Net

审查传输、消息注册与编解码、会话、发现、流控、统计和 GameNet 编排。重点验证取消、超时、断线、重复消息、并发收发、资源释放、状态机转换和异常传播，并检查热点路径中的多余分配、重复计算和不必要锁竞争；不扩展密码学、身份认证或抗攻击设计。

### 第六轮：跨模块精简

统一公共 API 命名和中文 XML 注释，清理确认无价值的重复测试、重复辅助代码与过时语法；能够以现代 C# 语法明显缩短并澄清代码时直接改用新式写法。测试精简只删除被更高层行为测试完全覆盖、且不承担边界或回归价值的用例。

### 第七轮：独立复审与发布验证

逐轮差异由独立审查者复核。最后重新审查跨模块契约，处理所有 Critical 和 Important 反馈，并执行完整 Debug 测试、Release 构建和源代码质量检查。

## 单轮工作流

每轮先记录具体问题和预期契约。行为修复或 API 调整遵循测试先行：新增最小失败测试，确认因目标问题失败，再做最小实现并运行相关测试。纯等价语法和注释修改以现有测试、编译器和源文本检查保护。

一轮只有在相关测试及 Release 构建通过后才算完整；完整轮次提交一次。提交后使用独立审查者检查该轮 Git 差异，Critical 与 Important 问题在进入下一轮前修复。若反馈修复改变了该轮实现，则将修复纳入该轮的补充提交，并在最终历史中保留清晰的审查轨迹。

## 测试策略

- 基线为 Debug 配置下 627 项测试全部通过，以及 Release 构建 0 警告、0 错误。
- 每个修复必须有能够描述外部可观察契约的回归测试；优先测试真实对象，避免仅验证 mock 调用。
- 对算法和状态机覆盖正常路径、边界输入、无效操作及重复操作。
- 对并发和异步代码使用可控时间源、确定性同步点和显式取消，避免依赖休眠或概率。
- 每轮运行最相关的测试项目；提交前运行整个 `Test` 项目和 Release 构建。
- 最终运行 `dotnet test .\SimpleFramework.sln --configuration Debug` 与 `dotnet build .\SimpleFramework.sln --configuration Release`。

## 非目标

- 不更换整体架构、ECS 模型或网络协议体系。
- 不跨项目随意移动源文件，不改变程序集边界，除非发现无法局部修复的明确设计缺陷。
- 不引入与当前目标无关的第三方运行时依赖。
- 不将 Net 网络安全加固或平台专项压力测试纳入发布门槛；性能问题通过代码审查和针对性测量处理，不强制建设完整基准体系。
- 不为了使用新语法而使用更晦涩或需要额外解释的写法。

## 完成条件

- 七轮范围均有审查证据，发现的问题均已处理或有明确的不修改理由。
- 不存在未解决的 Critical 或 Important 审查反馈。
- 公共 API 的名称、契约和中文 XML 注释一致，源文本质量检查通过。
- 关键行为和回归测试覆盖实际修改，精简测试未降低重要契约的保护能力。
- 已检查主要热点路径，不存在可通过小规模调整消除的明显性能浪费。
- Debug 全量测试通过，Release 全量构建 0 警告、0 错误。
- 分支提交按完整轮次组织，可独立审阅和回溯。
