## Findings and Decisions

- Important: `NetMessenger` allowed synchronous and asynchronous exceptions from transport send delegates to escape APIs that otherwise return `NetSendResult`. This could also fault detached stats or flow work. The messaging boundary now records `TransportSendFailed`, returns `TransportFailed`, and releases the in-flight reservation in `finally`; regressions prove the next send is not left queue-blocked.
- Important: `NetStats` detached pong sends from its synchronous ping handler. Packet handling could complete while the response send remained active, and a fault was not observed by that handler. The ping handler is now asynchronous and awaits the pong send through normal messenger containment.
- Important: `GameNet` directly trusted transport start, connect, system-send, stop, and disconnect calls not to throw. Thrown failures escaped structured session results or could fault detached peer-directory broadcasts. Narrow transport-call boundaries now convert exceptions to diagnostics and structured failures. Host/join/stop remain retryable where state was not committed; client leave clears local state but reports disconnect failure instead of false success.
- Moderate performance: TCP framing allocated one new four-byte prefix array for every write and another for every read. Each connection now owns one read prefix and one write prefix. The sole read loop owns the read buffer; the existing `WriteLock` owns the write buffer during each frame, preserving concurrent-send correctness. Payload arrays remain intentionally owned by packet events.
- Documentation: the supplied baseline filter used a nonexistent namespace and selected zero tests. The Task 5 plan now uses `FullyQualifiedName~Net`, which selected 277 baseline tests and 284 final tests.
- Important review repairs: caller/Stop cancellation during the join handshake now retains cancellation identity and leaves the client retryable. TCP sends distinguish cancellation while waiting for the per-connection write lock from cancellation or failure after a frame may have started; only the latter removes the connection before another writer can reuse the stream.
- Important review repairs: typed messenger sends and direct session-control sends now have separate diagnostic ownership, so one transport failure increments `ErrorCount` exactly once. Kick reports disconnect-notice failure after still completing a successful disconnect, while a thrown disconnect keeps the peer registered for a retry.
- Retained by design: JSON packet envelopes and their payload copy remain the readable V1 protocol; memory transport still copies sends to preserve sender/receiver ownership; TCP unreliable sends remain unsupported; request/flow/discovery time uses the configured `TimeProvider`; security features remain out of scope.

## Changes

- Added seven deterministic regressions: synchronous/asynchronous send exceptions, awaited pong send completion, thrown transport start/connect/stop, and thrown client disconnect cleanup.
- Centralized transport exception mapping at messaging and `GameNet` session boundaries without changing public API shape.
- Reused TCP frame-prefix buffers with `BinaryPrimitives` while retaining the existing single-reader and serialized-writer model.
- Corrected the focused Net test filter and appended every concrete repair to the full-review plan before its production change.
- Added an internal TCP frame-writer injection seam without changing either public constructor, plus deterministic write-lock cancellation and partial-prefix/payload failure tests.
- Added deterministic GameNet regressions for join-send cancellation, typed-send exceptions, Kick send/disconnect failures, and detached peer-directory broadcast failures.
