## Findings and Decisions

- Critical: `SystemGroup.Update` allowed reentrant dispatch. A regression test reproduced an actual stack overflow and test-host crash. The group now rejects nested update before sorting or dispatch and recovers through the existing `finally` guard.
- Important: `Archetype.Add` appended the entity and earlier columns before discovering a missing later component, corrupting row/column alignment. It now validates and collects the complete row before committing storage changes.
- Important: `BufferedEntity` identity used only a buffer-local integer, so equal local IDs from different buffers aliased during command recording and result resolution despite the approved ownership contract. Identity now includes a unique command-buffer owner, and foreign buffered targets are rejected before recording.
- Important: `TypeSignature` initially stopped at assembly-qualified identity, but collectible runtime types can be distinct while sharing both `FullName` and assembly identity. Ordering now uses names for useful stability and a thread-safe weak runtime identity ID as the final tie-breaker, so comparator equality means reference-equal `Type`. Monotonic IDs make the final tier transitive; `ConditionalWeakTable` is thread-safe and its values do not reference keys, so collectible types are not rooted.
- Important: `EntityPrefab.With<T>` keyed components by declared `typeof(T)`, so widened calls could accept one runtime duplicate under two keys or reject two distinct runtime types under the shared interface key. It now keys by `component.GetType()`, matching world creation and exact signature/column lookup.
- Important: retaining commands after a failed non-transactional playback made retry unusable: the successful prefix repeated, the same immutable command failed again, and no partial result could resolve created placeholders. Every playback attempt now consumes one generation in `finally`, invalidates its handles, preserves completed prefix effects, skips the suffix, and allows a fresh batch; successful results keep resolving their completed generation.
- Important: `Query.GetArchetypes` returned its mutable internal `List<Archetype>` as `IReadOnlyList`, allowing a cast to clear query state. It now returns one cached read-only wrapper, avoiding both mutation and per-access copies.
- Moderate: null class components were inconsistently dereferenced, recorded, or stored. `World`, `CommandBuffer`, and `EntityPrefab` now reject them at public component-taking boundaries before state changes, with explicit parameter diagnostics.
- Moderate: `EcsSystem` accepted a null world into its protected non-null contract. Construction now fails immediately with `ArgumentNullException` naming `world`.
- Documentation: the supplied baseline filter named a nonexistent namespace and selected zero tests. The plan now uses `FullyQualifiedName~Test.ECS`, which selected all 97 baseline ECS tests and all 111 final ECS tests.
- Documentation: usage text incorrectly limited components to value types and allocated a new query inside every example frame. It now documents struct/class/null semantics, caches system queries, and includes accurate command-buffer, prefab, ownership, ordering, and non-transactional playback examples.
- Retained by design: entity IDs remain static and monotonically increasing across worlds; invalid `DestroyEntity` remains a no-op returning false; failed command playback does not roll back earlier effects or return a partial result; prefab class components remain shared references; queries use lazy archetype-version refresh without subscriptions or disposal; missing dependencies and cross-manual-order edges remain ignored; disabled systems remain in dependency validation; direct structural mutation during query traversal remains rejected.
