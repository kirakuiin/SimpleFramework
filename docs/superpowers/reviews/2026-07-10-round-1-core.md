## Contracts Checked

- `Directory.Build.props` consistently targets `net8.0`, enables implicit usings and nullable analysis, and separates Debug/Release output. `global.json` pins SDK `9.0.0` with `latestMinor` roll-forward and no prerelease SDK. The root project excludes every subproject/test source tree and references Utility explicitly; no project-contract edit was required.
- Domain creation was traced through lazy `Instance`, non-creating `GetInstance`, and independent initialized `Create`. Parent lookup uses a weak parent reference, while `AddChild` records strong lifecycle ownership. Duplicate child addition, parent replacement, cycle detection, owned-child release, lookup-only parent survival, and singleton reset all have direct tests.
- System/model normal registration injects the domain and initializes once. Alias registration of the same instance remains deduplicated by reference. Replacement releases only the last lifecycle-managed key; system release precedes model release. Utility aliases never create lifecycle ownership, including dual-role runtime types.
- Missing component lookup remains nullable for `Get*`, boolean for `TryGet*`, and now throws intentional `InvalidOperationException` from `Require*`. Messages retain both requested component type and domain type.
- Domain events remain local and are cleared on domain release; parent lookup does not affect them. `EventBus.Global` remains independent. Listener removal during dispatch uses a snapshot, empty events are removed, stale unregister tokens cannot delete newly registered events, and clearing the bus invalidates old event instances safely.
- Commands and queries receive the sending domain immediately before execution. Void/result commands and result queries preserve their existing virtual dispatch hooks. No production change required.
- `BindableProperty<T>` keeps its comparer per instance, handles nullable values, suppresses equal-value notifications, keeps unregister tokens idempotent, and now reads the overridable old value once per changed assignment before reading the delivered post-write value.
- Release failure paths were traced for child, component, and domain hooks. Domain cleanup still aggregates independent release failures, clears registrations/events/parent state, resets the registration guard, and resets a matching singleton. Reentrant release now cannot duplicate lifecycle callbacks.

## Findings and Decisions

- Important — `AbstractDomain.RegisterSystemAs`/`RegisterModelAs` replaced the container entry before releasing the previous last lifecycle reference. If cleanup threw, lookup exposed an uninitialized replacement. Registration now leaves the previous entry visible until cleanup succeeds, propagates the original cleanup exception, and initializes the replacement only afterward.
- Important — failed component initialization left the failed instance registered and lifecycle-managed. Registration now rolls back the attempted key and restores a prior still-valid entry when that entry was not released.
- Important — replacement cleanup could recursively register another component, causing nested replacement and leaking an initialized intermediate instance. A dedicated lifecycle-cleanup guard now rejects nested registration, resets in `finally`, and preserves the old visible registration.
- Important — a component could call `Domain.UnInitialize()` from its own release callback and receive a second lifecycle callback. Reentrant release is now an idempotent no-op while the outer cleanup owns the operation.
- Important independent-review finding — `CustomUnRegister.UnRegister` cleared its callback only after invocation, so a throwing callback remained stored and ran again on a later `UnRegister` or `Dispose`. The callback is now captured and cleared before invocation; the original exception still propagates, while every later call is a no-op.
- Moderate — `RequireSystem`, `RequireModel`, and `RequireUtility` intentionally threw `NullReferenceException`, which misidentified a missing registration as a runtime dereference defect. They now use documented `InvalidOperationException` contracts.
- Moderate — `Container.Register` relied on `Debug.Assert` for null rejection, so Release accepted a null value into the component map. It now throws `ArgumentNullException` before mutation in all configurations.
- Moderate — `EventContainer.GetEvent` returned runtime null through an unchecked cast and null suppression while declaring a non-null result. Its unconstrained event result now carries `MaybeNull` metadata; `AddEvent` returns the created event so `EventBus.Register` remains warning-free without suppression while preserving support for value-type `IEvent` implementations.
- Minor performance/clarity — `BindableProperty<T>.Value` called the virtual getter twice before writing. It now captures the old value once; notification still observes the post-write getter result.
- Documentation — scoped public/protected declarations with missing or inaccurate contracts received Chinese XML documentation or `inheritdoc`; registration failure, missing component, nullable event, lifecycle cleanup, trait, extension, and abstract hook semantics now match implementation.
- Minor independent-review documentation findings — `IDomain.UnInitialize` now states that cleanup failures are aggregated into `AggregateException`, and `EventContainer.GetEvent<T>` now states that a miss returns `default(T)`, which is null only for reference-type events.
- Retained — weak lookup inheritance, strong child ownership, local event boundaries, mutable `EventBus.Global`, command/query domain reinjection, component release ordering, and utility non-lifecycle behavior match the approved contracts and tests. No architecture or dependency change was justified.
